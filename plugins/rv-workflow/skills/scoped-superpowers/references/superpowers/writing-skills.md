# Writing Skills

Treat a skill as executable process documentation. Define realistic trigger scenarios and the failure the skill must prevent before writing instructions. When the workflow is complex enough to justify behavioral testing, observe the baseline failure, add the smallest guidance that corrects it, and re-run the scenario.

Keep the discovery description focused on when to load the skill, not a shortcut summary of its procedure. Put shared invariants in `SKILL.md`, conditional detail in linked references, and deterministic repeated mechanics in scripts. Avoid generic advice, duplicated manuals, and references to unavailable skills or tools. Validate frontmatter, links, invocation policy, bundled resources, and representative behavior before distribution.
