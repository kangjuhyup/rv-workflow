# Writing Plans

Write an implementation plan only when sequencing or coordination is non-obvious. Ground it in repository evidence and the accepted specification. Name the exact files or modules involved, dependency order, public contracts, migration or compatibility concerns, and the command that verifies each step.

Break work into small outcome-oriented tasks rather than vague phases or line-by-line code prescriptions. Separate tests from production changes when the workflow requires an executable contract. Identify decisions that still need user acceptance instead of hiding them as assumptions. Keep the plan current when evidence changes, but do not turn a straightforward edit into ceremony.
