# Verification Before Completion

Before stating that work is complete, fixed, clean, or passing, identify the command or inspection that proves each claim. Run it fresh after the last relevant change, read the full result, confirm the exit status and failure count, and report the evidence alongside the claim.

Code review, previous runs, generated output, or another agent's success report are not substitutes. A passing test does not prove a build; a passing linter does not prove runtime behavior. If a required check cannot run, state the exact limitation and the narrower evidence obtained. Never mark a tracked task complete merely because time or token budget is low.
